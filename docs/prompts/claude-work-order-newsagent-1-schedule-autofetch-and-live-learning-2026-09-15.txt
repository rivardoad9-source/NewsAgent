== 1. AUTO-FETCH JADWAL BLS + FOMC DENGAN VALIDASI + ALARM CAKUPAN (P0) ==
1a. Script baru (mis. `scripts/fetch_schedule.py`) yang mengambil halaman resmi BLS
    (`https://www.bls.gov/schedule/news_release/` dan/atau halaman per indikator) dan kalender FOMC
    (`https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm`), lalu menulis hasilnya ke
    `data/schedule.json` dengan bentuk SAMA seperti konstanta sekarang: `{"BLS": {indikator: ["YYYY-MM-DD", …]},
    "FOMC": ["YYYY-MM-DD", …]}`. Bentuk akhir boleh JSON (bukan file .py generated) — jelaskan pilihan lu.
1b. `src/calendar.py` memakai file itu sebagai sumber UTAMA **kalau ada dan lolos validasi**; kalau tidak ada /
    tidak valid → jatuh ke konstanta hardcode yang sekarang. `upcoming()`, `last_release_date()`, `last_releases()`
    signature dan perilakunya tidak berubah untuk pemanggil.
1c. Validasi SEBELUM menerima hasil fetch (taruh di fungsi terpisah + test): format tanggal ISO valid; urutan naik;
    jarak antar-rilis masuk akal (CPI/PPI bulanan ≈ 20–45 hari, NFP bulanan); minimal N tanggal per indikator per
    tahun; tidak semua tanggal di masa lalu; `FOMC` maksimal 8–9 tanggal per tahun. **Halaman error/template
    (judul/tabel tidak ketemu) harus DITOLAK**, bukan di-parse jadi jadwal kosong yang terlihat sah.
1d. Alarm cakupan: kalau tanggal terjauh < **60 hari** dari hari ini, atau ada indikator high-impact dengan 0 entri
    untuk tahun depan → tulis `data/schedule_status.json` (mis. `{"last_date": …, "days_left": …, "ok": false,

    (terakhir 2026-12-23, nol 2027) — kalau script lu jalan hari ini, alarm harus menyala.
